The checks

Checked before an alert is raised.

  • Are the features schema-valid?
  • Is Random Forest ready to vote?
  • Are all 66 values finite?
  • Does Isolation Forest agree?
  • Are both model artifacts loaded?
  • Should disagreement raise suspicion?
  • Is hybrid fusion able to score risk?
  • Is the decision explainable for triage?

✕ If a required check fails, ThreatLens stops the prediction.

One flow / five decisions

The alert only lands after the boundary says yes.

ThreatLens evaluates deterministic facts in order. A refusal is returned as a useful runtime outcome, not discovered later in a dashboard.

  1. 1
    Are the features valid?

    Schema order, finite values, 66 CICIDS fields.

    PASS
  2. 2
    Can Random Forest classify it?

    Supervised vote, BENIGN or DDoS, class signal.

    VOTE
  3. 3
    Does Isolation Forest agree?

    Anomaly score, normal vs outlier, unsupervised signal.

    CHECK
  4. 4
    Should hybrid fusion escalate?

    Agreement, disagreement, suspicion, risk 0–100.

    SCORE
  5. 5
    Raise the explainable alert

    Only now does the decision become a triage-ready alert.

The honest boundary

Deterministic hybrid scoring, with a clear trust boundary.

ThreatLens ships deterministic controls for feature validation, Random Forest and Isolation Forest votes, hybrid fusion, risk triage 0–100, explainable alert output, and SQLite persistence of scored occurrences.

Health is not detection quality. A green status only means artifacts and the database loaded. Broader live capture, traffic blocking, calibrated attack probability, and production access control still require additional systems.
