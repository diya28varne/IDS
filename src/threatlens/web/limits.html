ThreatLens is a research prototype for hybrid IDS inference on CICIDS-style network-flow features. This handbook states what the running code does — and what a green health check must never be mistaken for.

Trust boundary

Model output is data for investigation, even when the decision looks decisive. Random Forest votes, Isolation Forest anomaly flags, hybrid fusion, and the risk score must not be promoted into proof that an attack occurred. 

POST /predict
{
  "features": { "Flow Duration": 0, "...": "66 schema fields" }
}

→ decision · rf_vote · if_vote · risk_score · explanation

This is a narrow honesty boundary at the investigation edge. It keeps triage scores from being treated as calibrated attack probability or live defence authority. Clients never upload model files, database paths, or filesystem locations — artifacts load once on the server.

Inference path

Hybrid path

Each prediction validates 66 finite numeric features in trained schema order, then runs supervised and unsupervised votes before fusion:

  1. Validate — schema order, finite values, no client-chosen artifacts.
  2. Vote — Random Forest returns BENIGN or DDoS.
  3. Check — Isolation Forest returns normal or anomaly.
  4. Fuse — hybrid rules emit BENIGN, SUSPICIOUS, or DDoS plus risk 0–100.
  5. Explain — structured reason, supporting scores, optional SQLite persist.

Persistence

Alert occurrences can be stored in SQLite for history and dashboard aggregates. The database path is server-configured (THREATLENS_DB_PATH or the default under artifacts/). The UI and API never accept a client-supplied DB path.

Reference

Implementation

  • FastAPI loads RF/IF joblib artifacts at startup into a shared model bundle.
  • Static Mycelium-inspired UI is served from /; React dashboard proxies the same API.
  • Offline training and metrics live under artifacts/models/ and docs/EVALUATION.md.
  • Architecture of the implemented system is documented in docs/ARCHITECTURE.md.

Limits

  • It does not capture live packets or block network traffic.
  • It does not treat /health readiness as detection accuracy.
  • It does not claim calibrated P(attack) from the risk score.
  • It does not include authentication, multi-tenant access control, or auto-retraining.

Accuracy claims belong in offline evaluation docs — not in a successful health chip.
